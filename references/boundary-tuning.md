# 句边界：为什么总把单词劈成两半，以及怎么调

这是整个流程里唯一需要"手感"的地方。**目标不是"切得刚好"，而是"宁可多留 0.1s，
也绝不能把一个词切到两句里去"** —— 听的人遇到半截词会被打断，遇到下一句开头重复更崩溃。

## 核心机制（`split.py`）

1. **词级窗口夹住边界**：边界 i 只允许落在
   `[句i 最后一个词的起点 − 0.05, 句i+1 第一个词的起点 + 0.40]`
   - 下界：保证句 i 至少完整发出最后一个词
   - 上界：保证句 i+1 的第一个词没被上一句吃掉

2. **`+0.40` 不是拍脑袋**：实测 whisper 的词时间戳整体偏早 200–350ms。
   不给这个余量，真正的句间静音会被排除在窗口外，边界只能落在尾音上 → 词被劈开。
   这是"修了两轮才修好"的根因。

3. **取窗口内【最后】一段够长（≥60ms）的静音的中点**，而不是【最长】的静音：
   句间停顿一定是窗口内最后一段静音；取最长会误选句内逗号处的停顿。

4. **窗口内没有静音** → 退化为能量最低点（`quietest()`），并轻微偏好靠后。

5. **静音阈值自适应**：`max(0.0015, 全片 RMS 中位数 × 0.10)`，
   避免底噪大的录音（教室录音、手机外放转录）整片判不出静音。

6. 收尾：`trim_silence()` 裁掉片段首尾过长静音（进 0.12s / 出 0.20s），点开就出声。

## 调参入口

| 位置 | 参数 | 症状 → 调整 |
|---|---|---|
| `window()` | `hi = w_start + 0.40` | 下一句开头被吃 → 加大到 0.5；上一句尾巴拖太长 → 减到 0.3 |
| `window()` | `lo = max(lo, hi - 2.5)` | 边界跳到句内（片段忽长忽短）→ 减小到 1.0～1.5 |
| `last_silent()` | `min_len=0.06` | 语速快、停顿极短 → 减小到 0.04 |
| `build_bounds()` | `percentile(rms,50)*0.10` | 底噪大、判不出静音 → 系数加大到 0.15～0.20 |
| `trim_silence()` | `pad_in/pad_out` | 觉得起手太急 → pad_in 加到 0.20 |
| `tighten()` | `max_gap=2.5` | 一句里被并进了后面的题目 → 减小到 1.0 |

## 验证手段

- `python scripts/verify_clips.py --work ./out`：把每个片段**单独重新识别**，
  比对"听到的"与"标注的"：
  - 溢出：听到的末词出现在下一句开头 → 会听到下一句开头重复
  - 缺失：标注的末词在音频里找不到 → 尾音被切掉
  抽查用 `VERIFY_IDS=1,2,3,40,41` 只跑几句，全量跑比较慢。
- 人工听相邻两句是最可靠的判据，自动化只能缩小范围。

## 已知残留

语速极快、连词处几乎不停顿（如"a lot of"连读），窗口里可能真的没有静音，
此时由 `quietest()` 兜底，偶尔会有 10–20ms 的偏差 —— 不影响听懂，可接受。
